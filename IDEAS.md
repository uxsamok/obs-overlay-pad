## 2026-10-31 · Библиотека медиа-ассетов

**Статус:** обсуждается

Папка (локальная или на NAS) с подпапками картинок и видео; пульт сканирует её и показывает ассеты по группам, а нажатие временно выводит выбранный в эфир, не меняя структуру сцен OBS. Подход: постоянные источники-слоты (один `image_source`, один `ffmpeg_source`), у которых путь меняется через `SetInputSettings`; «добавить навсегда» — через `CreateInput`. Гигиена: после стрима чистить источники-файлы, перед созданием проверять `GetInputList`, чтобы не плодить дубли. Каждая кнопка хранит свою привязку (источник или файл + настройки) — ключ кнопка, а не путь к файлу; большинство кнопок ведут на готовые источники OBS, 2–3 слота — для временных файлов, и для оператора нет разницы, какую кнопку он нажимает.

Открытые вопросы:
- порядок в папке и похожие версии одного файла;
- отдельное приложение или модуль (склоняемся к модулю с отдельным сервисом сканирования);
- теги и пометка готовности ассетов.

Дополнения:
- NAS: рабочие файлы переносим на NAS, чтобы все машины, включая компьютер с OBS, видели их по одному пути.
- Производительность: создавать и удалять медиа- и браузерные источники во время эфира тяжелее, чем менять путь, поэтому на эфире только слоты.
- Альтернатива: браузерный источник — локальный файл, ссылка с данными или своя страница-галерея; минус в задержке загрузки и отдельной связи с пультом.
- Слайд-шоу изображений, встроено в OBS: папка, команды следующий и предыдущий; минус — неудобно выбрать одну нужную картинку.

Рассмотрено и отклонено: Syphon / Spout. Отклонены: для готовых файлов усложняют, стандартные источники проще и надёжнее.

## 2026-10-31 · Индикатор здоровья стрима

**Статус:** в работе

Компактный индикатор в существующем ряду из четырёх статусов OBS в левом верхнем углу пульта. Он показывает здоровье стрима полоской, которая растёт вместе с проблемами: маленькая зелёная — всё хорошо, растущая жёлтая — назревают проблемы, полная красная — реальная проблема. По нажатию открывается окно с подробностями из OBS (через `GetStreamStatus` и `GetStats`): перегрузка сети, пропущенные кадры, FPS и подсказка, что делать. Принцип тот же, что у отчёта синхронизации: тихо, когда всё нормально, сигнал при риске, полный отчёт по запросу.

## 2026-10-31 · Публичный релиз приложения

**Статус:** обсуждается

Друг предложил показать пульт другим стримерам и сделать его публичным. Варианты хостинга: GitHub Pages (бесплатно, обновляется сам при push, но возможности ограничены) или свой сайт с видеоинструкциями и понятным описанием для новичков; компромисс — приложение на GitHub Pages, а отдельный сайт-витрина. Страницу пульта можно разместить где угодно, даже на публичном сайте: скрипт в браузере сам подключается по WebSocket к локальному IP компьютера с OBS на порт 4455, хостить само подключение не нужно; работает, когда планшет и компьютер с OBS за одним роутером и оба в сети. Брандмауэр: на Windows для порта 5757 (наш сервер) есть правило для частных сетей, а порт OBS WebSocket 4455 заработал сразу без изменений; на Linux ufw/iptables могут блокировать 4455 и потребовать ручное правило, зато mDNS через Avahi на Linux надёжнее, чем на Windows. Браузер не может сканировать локальную сеть из соображений безопасности, поэтому автопоиск возможен через mDNS, а ручной ввод IP остаётся запасным вариантом. Безопасность: открытый порт 5757 в публичной или чужой Wi-Fi виден всем в этой сети — для стационарного домашнего ПК это приемлемо, для ноутбука рискованно.

Открытые вопросы:
- HTTPS-блок: страница с GitHub Pages или любого HTTPS-сайта не сможет подключиться к OBS по незащищённому ws:// на локальный адрес — браузер заблокирует. Нужно решить: проксировать WebSocket через сервер на 5757, или хостить страницу по HTTP.
